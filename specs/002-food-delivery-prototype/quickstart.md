# Перевірка прототипу

Інструкція описує перевірку майбутньої реалізації з кореня репозиторію у Windows PowerShell. Потрібен встановлений JDK 17 або новіший; зовнішні бібліотеки, база даних та мережа не використовуються.

## Компіляція та запуск

```powershell
$OutputEncoding = [Console]::OutputEncoding = [System.Text.UTF8Encoding]::new()
$sources = Get-ChildItem .\src -Filter *.java | ForEach-Object { $_.FullName }
javac --release 17 -encoding UTF-8 -d .\out $sources
java "-Dfile.encoding=UTF-8" -cp .\out Main
```

Очікується успішна компіляція й завершення одного автоматичного запуску. Тимчасові `.class`-файли з'являються в `out`; їх не слід додавати до репозиторію.

## Наскрізні перевірки

1. У початку виводу є формування кошика й замовлення, рішення ресторану, приготування, готовність, забір кур'єром, відстеження, завершення та відгук.
2. Успішний сценарій завершується статусом `Delivered`, а відгук приймається лише після нього.
3. Після успішного сценарію показуються три окремі невдалі сценарії: порожній кошик, відхилення рестораном і неможливість забору. Вони не показуються як `Delivered`.
4. Вивід користувачеві, включно з причинами відмов і маршрутною імітацією, подано українською.
5. Повторні `confirm()`, `markReady()`, `start()` і `complete()` не створюють суперечливого стану; відгук для незавершеної доставки, повторний відгук і оцінка поза межами 1–5 відхиляються.
6. Звірити класи, атрибути, конструктори, методи, зв'язки, виклики та стани коду з `docs/class.mmd`, `docs/sequence.mmd`, `docs/state.mmd` і картками `docs/crc.xlsx`; запускний клас також задокументований.
7. Перевірити README-команди, виконавши їх із чистого каталогу `out` та встановленим JDK. Переконатися, що компіляція не вимагає мережі чи сторонніх бібліотек.

## Очікуваний результат

Застосунок компілюється стандартним JDK і за один запуск виводить усі чотири визначені сценарії з правильними станами та українськими повідомленнями. UML, CRC-картки й README описують ту саму реалізацію.
