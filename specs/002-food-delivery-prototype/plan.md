# План реалізації: Імітаційний прототип служби доставки їжі

**Гілка**: `002-food-delivery-prototype` | **Дата**: 2026-11-02 | **Специфікація**: [spec.md](spec.md)

**Вхід**: Специфікація функції `specs/002-food-delivery-prototype/spec.md`.

## Підсумок

Створити простий Java-консольний прототип, який без зовнішніх залежностей демонструє успішний цикл замовлення, приготування, доставки й відгуку, а потім порожній кошик, відхилення рестораном і неможливість забору. Класи та їхні зв'язки реалізують наявні діаграми `docs`, а всі повідомлення користувачеві будуть українською. Програма працюватиме в пам'яті; зовнішні операції імітуються текстом у консолі.

## Технічний контекст

**Мова/версія**: Java 17 без preview-функцій; компіляція з `--release 17`.

**Основні залежності**: Лише JDK (`javac`, `java`); сторонні бібліотеки й система збирання не потрібні.

**Зберігання**: Об'єкти в пам'яті лише на час демонстрації; база даних і файлове збереження не використовуються.

**Тестування**: Збирання командою `javac`, запуск сценарію через `java`, перевірка послідовності виводу, локалізації та кінцевих станів основного і трьох невдалих сценаріїв. Тестовий фреймворк не додається.

**Цільова платформа**: Консоль із JDK 17 або новішим; інструкції запускаються з кореня репозиторію в PowerShell.

**Тип проєкту**: Одномодульний навчальний Java CLI-застосунок.

**Цілі продуктивності**: Не застосовуються; сценарій завершується за один локальний запуск.

**Обмеження**: Без мережі, бази даних, реальної оплати чи маршрутизації; консольні повідомлення й вихідні файли мають кодування UTF-8. Модель станів, класи та відповідальності узгоджуються з `docs`.

**Масштаб**: Дев'ять предметних класів та інтерфейс `IDeliveryStatus`, запускний клас, один успішний і три невдалі демонстраційні сценарії, оновлений кореневий `README.md` та звірені UML/CRC-артефакти.

Якщо під час реалізації буде потрібен допоміжний клас, його відповідальність і відповідні зв'язки спершу відобразити в UML та CRC-картках.

## Підхід до реалізації

1. Реалізувати предметні класи згідно з `docs/class.mmd`: конструктори, перевантаження `Order.addItem`, `final` для `getId()`, реалізацію `IDeliveryStatus` та передавання `MappingService` через конструктор `Delivery`.
2. Реалізувати перевірки замовлення, відгуку та переходів станів за `docs/state.mmd`; повторна або недопустима подія не повинна створювати суперечливий успішний стан.
3. Реалізувати `Main` як детермінований запускний компонент: спочатку успішний наскрізний сценарій, потім порожній кошик, відхилення рестораном і неможливість забору.
4. Додати короткий україномовний `README.md` з призначенням прототипу, межами імітації та робочими командами для PowerShell.
5. Зібрати й запустити програму, звірити кожен клас, метод, зв'язок, виклик та перехід стану з `docs`; у разі невідповідності виправити код або відповідні документаційні артефакти.
