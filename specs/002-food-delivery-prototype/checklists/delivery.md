# Чекліст вимог: Імітаційний прототип служби доставки їжі

**Призначення**: Оцінити повноту, ясність і узгодженість вимог до демонстраційного прототипу служби доставки їжі.
**Створено**: 2026-11-02
**Функція**: [spec.md](../spec.md)

**Примітка**: Цей користувацький чекліст створено командою `/speckit-checklist` на основі контексту функції.
**Відповідальність за перевірку**: Чекліст призначений для рецензента. Позначайте пункт `[x]` лише якщо критерій якості вимог задоволений.
**Значення позначок**: `[x]` означає, що критерій перевірено і вимоги йому відповідають; це не означає завершення реалізації.

## Повнота вимог

- [ ] CHK001 Чи охоплюють вимоги всі етапи основного циклу — від кошика й вибору часу до відгуку? [Completeness, Spec §FR-002]
- [ ] CHK002 Чи окремо визначено очікуваний результат і пояснення для кожного з трьох невдалих сценаріїв? [Completeness, Spec §US1, SC-001, SC-005]
- [ ] CHK003 Чи повністю визначено склад предметної моделі, запускного компонента та необхідних документаційних артефактів? [Completeness, Spec §FR-007–014]

## Ясність вимог

- [ ] CHK004 Чи уточнено, за якими критеріями час доставки вважається доступним або недоступним? [Clarity, Spec §US1, FR-002, Gap]
- [ ] CHK005 Чи визначено, що саме робить консольне повідомлення «зрозумілим» для кожного результату сценарію? [Clarity, Spec §FR-003–004, SC-001–002]
- [ ] CHK006 Чи однозначно задані команди, передумови та версія JDK для компіляції й запуску, які мають бути наведені в README? [Clarity, Spec §FR-005–006, Gap]

## Узгодженість вимог

- [ ] CHK007 Чи однаково визначені стани, події, повторні переходи та відновлення після перешкоди у вимогах і посиланнях на діаграму станів? [Consistency, Spec §FR-010]
- [ ] CHK008 Чи узгоджені вимоги до кількості сценаріїв, їхньої послідовності та кінцевих результатів у FR, сценаріях приймання й критеріях успіху? [Consistency, Spec §US1, FR-002, SC-001, SC-005]
- [ ] CHK009 Чи не суперечать одне одному вимоги про відповідність документації коду та статус UML/CRC як джерела моделі? [Consistency, Spec §FR-011–014, Assumption]

## Якість критеріїв приймання

- [ ] CHK010 Чи можна об'єктивно визначити виконання кожного критерію успіху, зокрема повноту сценаріїв і документації? [Measurability, Spec §SC-001–007]
- [ ] CHK011 Чи задають критерії приймання спостережувані результати для валідації замовлення, життєвого циклу та відгуку? [Acceptance Criteria, Spec §US1–US2]

## Покриття сценаріїв

- [ ] CHK012 Чи достатньо повно й однозначно описано основний сценарій для всіх трьох ролей та переходів між ними? [Coverage, Spec §FR-001–002, SC-001]
- [ ] CHK013 Чи визначено вимоги до скасування, очікування кур'єра, перешкоди та відновлення, а також повторних або недопустимих подій? [Coverage, Spec §FR-010, US2]
- [ ] CHK014 Чи визначено, які результати мають бути для кожної помилки оформлення, відхилення рестораном і неможливості забору? [Coverage, Spec §US1, FR-010, SC-005]

## Покриття граничних випадків

- [ ] CHK015 Чи повністю специфіковано межі валідації позиції кошика, часу доставки, рейтингу та повторного відгуку? [Edge Case, Spec §US1–US2, Gap]
- [ ] CHK016 Чи визначено для кожного завершального невдалого стану, що він не може бути представлений як успішна доставка або підстава для відгуку? [Edge Case, Spec §US2, FR-010]

## Нефункціональні вимоги

- [ ] CHK017 Чи охоплюють вимоги всі обмеження прототипу щодо українських повідомлень, кодування, мережі, бази даних і сторонніх залежностей? [Completeness, Spec §FR-003–005, SC-002, SC-007]
- [ ] CHK018 Чи явно визначено, що продуктивність, реальні інтеграції та інтерактивна робота не є критеріями цієї демонстрації? [Scope, Spec §FR-004–005, Assumption]

## Залежності та припущення

- [ ] CHK019 Чи задокументовано, які наявні діаграми та CRC-картки є джерелом вимог і як вирішуються виявлені розбіжності? [Dependency, Spec §FR-011–014, Assumption]
- [ ] CHK020 Чи чітко відокремлено обов'язкові передумови запуску (наявність JDK) від припущень про середовище та виключених можливостей? [Assumption, Spec §US3, FR-005–006]

## Неоднозначності та конфлікти

- [ ] CHK021 Чи уточнено невизначені терміни «доступний час», «зрозуміле повідомлення» та «узгоджені артефакти» вимірюваними критеріями? [Ambiguity, Spec §FR-002–006, FR-013]

## Примітки

- Позначайте пункт `[x]` лише після підтвердження якості відповідних вимог; невирішені питання залишайте непозначеними.
- `/speckit-implement` читає стан позначок як умову, але не змінює їх.
- `checklists/requirements.md` — окремий вбудований чекліст, життєвий цикл якого підтримують `/speckit-specify` і `/speckit-clarify`.
